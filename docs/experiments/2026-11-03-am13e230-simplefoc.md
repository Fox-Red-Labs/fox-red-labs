# Can SimpleFOC, the open-source motor library, drive a motor from the LP-AM13E230 and the DRV8376EVM?

Terms: [docs/vocab.md](../vocab.md), [LP-AM13E230 FAQ](../../am13e230/FAQ.md). FOC: field-oriented control. 1 kB = 1,024 bytes.

**Short answer.** The library builds and its control loop runs on the chip with no change to its files. Whether the motor turns is not known yet: the motor supply was off (bus sense 3.7 V, floating) when the image ran, and the image stops at that check by design.

**Question.** A hobby builder who knows SimpleFOC wants to run it on a TI board with a TI gate driver already wired to a Hall-sensor motor: does it port, how big, how fast a loop, and does the speed hold as well as TI's own FOC on the same hardware?

**Vendor position.** TI's AM13 motor solutions are TI's real-time library (`solutions/motor_control/ufoc_lp_bxl/` in the AM13E2x SDK 26.01.00.03); TI names no SimpleFOC support. SimpleFOC's README (read 2026-11-03) and its supported-hardware page list AVR, STM32, ESP32, Teensy, SAMD, RP2040, Portenta, nRF52 and one more wireless-chip family, and no TI part. Its own porting hook is `src/drivers/hardware_api.h`.

**What we tried.**

Board: one Rev E2 LP-AM13E230, DRV8376EVM on the BoosterPack headers, BLY171S-24V-4000 motor (the lab's `am13e230/bldc-drv8376` wiring). Tools: TI Arm Clang 5.1.1.LTS, AM13E2x SDK 26.01.00.03, SysConfig 1.28.0, DSLite. SimpleFOC 2.4.0 is in `third-party/simplefoc/`; the port is `ports/simplefoc/`.

The route (why, and what was rejected) is in `ports/simplefoc/README.md`: SimpleFOC unmodified, its `hardware_api.h` 6-PWM functions implemented on MCPWM4, a 62-line `Arduino.h`, no framework. Expectations were written before any run (same file): 20 to 30 kB, 6 to 12 us per pass, speed ripple above TI's 2.5 to 4.1 percent.

Runs, all with the flash backed up first (`frl backup`, main flash read twice, identical):

1. The real image, 2026-11-03 (`ports/simplefoc/results/2026-11-03-run1/`): sequence is wake the driver, read the bus, trim the sense offsets, then open-loop velocity (V/f ramp to 20 Hz electrical, 300 rpm) and closed-loop velocity on the Halls. It stopped at the bus check: 3.7 V.
2. A no-supply build (`FRL_DRY=1`, `results/2026-11-03-dry/`) that skips the bus, fault and alignment checks and runs both loops on a still rotor, to time the library.

**How far it got.**

Configure, compile, link, flash, boot, run: yes. Verified on the motor: no.

| Number | Value | Row |
|---|---|---|
| Flash | 23.1 kB (TI's Hall FOC port: 61.7 kB) | `port_flash_bytes`, `simplefoc-hall-foc-image` |
| Loop pass, open loop | 1.35k cycles mean, 1.57k worst (957,817 passes) | `simplefoc_loop_cycles` |
| Loop pass, closed loop (Hall polling, SVPWM) | 1.92k mean, 1.92k worst (714,602 passes) | `simplefoc_loop_cycles` |
| Port code | 160 lines + 146-line sketch; TI's port: about 650 changed lines | `simplefoc_glue_lines` |
| Speed ripple, peak current | waiting | `motor_speed_ripple`, `motor_phase_peak` |

All three expectations that could be checked held (flash 23.1 against 20 to 30 kB; both loop times inside their ranges).

**The line.** No technical limit was reached. The stop is the bench: bus sense 3.7 V on two runs, with the probe working and the driver awake. That reading looks like a floating input, not a supply (the sense outputs also read 0 counts).

What the spin will have to settle, written down now so the result cannot move the goalposts: the Hall angle SimpleFOC uses moves in 60 degree steps and the motor's sectors are uneven, so closed-loop speed ripple should come out above TI's 2.5 to 4.1 percent; the open-loop run should hold 300 rpm exactly with 0.3 to 0.5 A peak.

**Ideas we did not try.**

1. Switch the 12 V supply on (VBAT and PGND on the EVM), then rerun `ports/simplefoc/tools/run_simplefoc.py` (about 60 s, unattended, 1.5 A software trip, 8 s holds).
2. Fill the three waiting rows; compare the ripple with the same window definition TI's rows used.
3. Current-sense mode needs a `_configureADCLowSide` layer for SimpleFOC's `LowsideCurrentSense`; with it, SimpleFOC's FOC current loop could be compared with TI's directly.
4. The TMU would replace SimpleFOC's sine look-up if the loop time matters.

**Limits.** Not shown: the motor turning, any speed or current number, reverse, load, the current-sense mode, anything above 20 Hz electrical. The loop times are for a still rotor with the supply off, so they time the library's code, not a spinning run (the Hall polling path reads constant pins). The sense gain (1 V/A) is the lab's unverified assumption. The comparison with TI's FOC is of different work: TI's interrupt runs a current loop with the TMU; SimpleFOC's pass is voltage mode.
