# Does Zephyr's upstream board for the TI LP-MSPM0G3519 build, flash and run from a Mac?

**Short answer.** It builds and flashes with TI's chip table missing from OpenOCD, but TI's blinky sample does not run: the core stops in the NMI handler with an SRAM double-error event. The larger benchmark app was seen transmitting on its serial port, so the board is not dead; the blinky failure is unexplained.

Terms: [vocab](../vocab.md) (NMI, ECC, OpenOCD). Errors and fixes: [LP-MSPM0G3519 FAQ](../../mspm0g3519/FAQ.md). 1 kB = 1,024 bytes.

**Question.** Can a builder follow Zephyr's own getting-started path to a blinking LED on the LP-MSPM0G3519 from a Mac?

**Vendor position.** Zephyr 4.4.2 lists `lp_mspm0g3519` as a supported board (UART, GPIO and CAN) and its runner is OpenOCD. The xPack OpenOCD 0.12.0-7 in use has no MSPM0G3519 in its part table.

**What was tried.** A Zephyr 4.4.2 checkout, GCC 12.2 cross toolchain, xPack OpenOCD 0.12.0-7, probe <probe serial> on firmware 3.0.0.43, 2026-10-08. `west build -p always -b lp_mspm0g3519 samples/basic/blinky`, then `west flash` with `--openocd` pointing at the xPack build. Three runs. Then reading the chip with OpenOCD: program counter, the NMI index and the stack pointer.

**How far it got.** Configure, compile and flash passed on all three runs: build 52.8, 51.5 and 47.7 s, flash 4.5, 4.5 and 4.8 s. OpenOCD prints "Unidentified PART" for the chip and flashes anyway. The image is 11.8 kB of flash and 4 kB of RAM. It did not run: the program counter reads 0x4a0 (`z_SysNmiOnReset`, a `wfi` loop) on every sample, the active exception is 2 (NMI), and `SYSCTL.NMIIIDX` reads 6, which TI's header names SRAMDED (SRAM double-error detect). The benchmark app (`mspm0g3507/mcu-bench`) built for the same board was seen running: its program counter was inside the UART transmit function and varied between samples.

**The line.** The blinky stops in the NMI handler with SRAMDED set. Cause not established. Two facts that may matter: Zephyr's board file puts `sram0` at 64 kB (bank 0, the bank with ECC, per the comment in Zephyr's devicetree), and the build summary reports only 256 kB of flash and 64 kB of RAM although the chip has 512 kB and 128 kB.

**Ask.** If you have a blinking Zephyr build on an LP-MSPM0G3519, say which commit and which flags.
