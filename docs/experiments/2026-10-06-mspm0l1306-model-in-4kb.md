# How big a neural network can the TI LP-MSPM0L1306 run in 4 kB of RAM?

**Short answer.** Of four room-occupancy models trained for this project, the 636, 1,748 and 8.5k-weight ones run and match all 20 test vectors; the 8k model takes 84 to 100 ms at 32 MHz. The 32.8k-weight model does not link: its buffers alone need more than the chip's 4 kB of RAM.

Terms: [vocab](../vocab.md) (parameters, inference, quantize, .bss, linker). Errors and fixes: [LP-MSPM0L1306 FAQ](../../mspm0l1306/FAQ.md). 1 kB = 1,024 bytes.

**Question.** TI's Edge AI examples target bigger MSPM0 chips. Can a chip with 4 kB of RAM run a useful small model at all, and where is the ceiling?

**Vendor position.** MSPM0 SDK 2.11.00.07 has 13 Edge AI examples for the LP-MSPM0G3507 and none for the LP-MSPM0L1306 (folder listing, 2026-10-06). TI's published RAM figures for its smallest G3507 models are 2.26 kB and up (example READMEs).

**What was tried.** The four integer models of this project's room-occupancy benchmark (UCI Room Occupancy Estimation dataset; four sensor channels, 32 samples, 0 to 3 people), their prebuilt archives used unchanged: `model.a` (-Os) and `model_O3.a` (-O3). One model per image with its 20 test vectors, TI Arm Clang 5.1.1, 32 MHz, stack raised to 1 kB, RAM painted to measure the stack. Intel Mac, macOS 15.7.9, probe <probe serial>.

**How far it got.**

- occ_cnn_500 and occ_cnn_2k: link with 1.2 kB of static RAM; run; 20 of 20 vectors match class and all four outputs. Whole call 9.3 to 12.2 ms and 21.9 to 28.3 ms.
- occ_cnn_8k: links with 2.2 kB of static RAM; deepest stack 548 bytes; 20 of 20 match. Whole call 83.7 to 83.8 ms with the -O3 archive, 99.9 to 100.0 ms with -Os.
- occ_cnn_30k: compile passes, link fails: `program will not fit into available memory ... run placement with alignment fails for section ".bss"`, with `SRAM size: 0x1000 unused: 0xc00 max hole: 0xc00` for the harness alone.
- Cycle counts are within 6% of the same archives on the LP-MSPM0G3507.

**The line.** Between 8,484 and 32.8k weights, on RAM. **Unknown (suspected: Chip limit).** Only the prebuilt archives were tried; reusing buffers between layers and other code generators were not. The 32.8k-weight model's own buffers need 4.1 kB on the G3507's map, more than all of this chip's RAM before any stack. Flash is not the limit: the 32.8k-weight model's code and weights would fit in 64 kB.

- Train sizes between 8k and 30k to find the exact ceiling.
- Reuse one buffer for alternating layers, which the generated code does not do.
- Feed it the board's own light sensor and thermistor, a sub-dollar room sensor.
- TI's NNC compiler output for this chip, which it does not list as a target.

**Ask.** Anyone who has put a model on an MSPM0L-series part with a vendor tool chain: which tool, and how much flash did it leave?
