# Does ESPHome's Zigbee code fit on the TI LP-EM-CC2340R5's 36 kB of RAM?

**Short answer.** As a Zigbee end device, yes. ESPHome's generated switch-and-temperature device links for the LP-EM-CC2340R5 at 219.8 kB of flash and 32.0 kB of RAM, which leaves 4.0 kB of its 36 kB. As a Zigbee router, no: it needs 37.4 kB, 1.3 kB more than the chip has. Update, 2026-10-13: the [ESPHome CC27xx platform page](2026-10-13-esphome-cc27xx-platform.md) covers a run on this board. The end device joined Home Assistant's Zigbee network and answered commands; the router also ran after the heap was cut by 2 kB (it then has no heap left over). The link-only results below are unchanged; the run is on that page.

Terms: [vocab](../vocab.md). 1 kB = 1,024 bytes. An end device sleeps and talks to a router; a router relays for others and stays awake. The method, shim and ESPHome files are on the [CC2755P10 page](2026-10-13-cc2755p10-esphome-fit.md).

**Question.** The risk was RAM: TI's Zigbee example alone left 799 bytes on this chip with logging on. Does ESPHome fit beside the Zigbee stack once logging is off?

**Vendor position.** TI's Zigbee example for the board is a router, `zigbee/onoff_light`, built on ZBOSS R23 (ZBOSS is the Zigbee stack in TI's SDK for this chip). The chip has 36 kB of RAM. ESPHome's Zigbee component builds an end device by default and a router with `router: true`.

**What was tried.** `ports/esphome-ti/build.sh` with `BOARD=LP_EM_CC2340R5`, once with `ROLE=zr` and once with `ROLE=zed`: the same ESPHome C++, the same shim, TI's makefile flags for the Cortex-M0+ (`-mcpu=cortex-m0plus -mfloat-abi=soft`), FreeRTOS, logging off. The die-temperature read is a stub on this chip, because TI's Temperature driver is not configured. Baselines are TI's `onoff_light` built with the same logging-off SysConfig file and TI's heap size. The ESPHome builds add 4 kB of heap and give ESPHome a 2 kB task stack, as on the other page.

**How far it got.** Link, for the end device. For the router the linker stopped: `run placement with alignment fails for section ".data" size 0x3874 ... SRAM size: 0x9000 unused: 0x3310 max hole: 0x2f5c`. To read the size, the chip's RAM was enlarged in the linker file for one diagnostic link, `DIAG_RAM_SIZE`. It linked and showed 37.4 kB used against 36 kB available.

| Build (36 kB of RAM, logging off; bytes) | Flash | RAM | RAM left |
|---|---|---|---|
| TI `onoff_light`, router | 275,252 | 30,784 | 6,080 |
| ESPHome, router | 284,376 | 38,244 | -1,380 |
| TI `onoff_light`, end device | 215,912 | 25,293 | 11,571 |
| ESPHome, end device | 225,104 | 32,752 | 4,112 |

**The line.** The router stops on RAM, 1.3 kB over. ESPHome costs 7.3 kB of RAM and about 9 kB of flash on either role. The RAM is static data plus the 4 kB of heap added, which holds its 2 kB task stack. The end device's 4.0 kB of room is static; the real heap use was measured later (below). The end device's flash is 43 percent of the 508 kB region.

**What closed the router gap, and what it cost (run on the board).** The ZBOSS tables were not touched. Cutting the FreeRTOS heap from 10.9 kB (0x2BBC) to 8.9 kB (0x23BC) linked the router with 0.7 kB of RAM to spare (a smaller cut, to 0x25BC, did not link: the 140-byte RAM vector table needs an aligned hole that was not there). Flashed, that router joined 6 s later and answered 50 of 50 commands from Home Assistant over 7 minutes (median 97 ms in the first 20), but the heap ran dry: the minimum free bytes FreeRTOS recorded was 0. The end device at the full 10.9 kB heap peaked at 8.9 kB, leaving 2 kB. So the end device has margin and the router has none; whether a failed allocation was absorbed silently is not known. If you see a router on this chip stop answering after hours, raise the heap or cut the table sizes.

**Ask.** Which SysConfig Zigbee settings are safe to shrink on a CC2340R5 router, and what is the smallest neighbor table that still routes for five children? TI's public documentation does not say.

**Effort.** One more build script option and three baseline builds: 25 minutes after the CC2755P10 link existed.

**Verdict.** For the board that fits in a hobbyist's budget, ESPHome's Zigbee device works as an end device (2.0 kB of heap margin measured) and runs, with no margin, as a router.
