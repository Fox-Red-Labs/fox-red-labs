# Is the TI LP-AM13E230 faster than a C2000 on the C2000's own motor-control code?

**Short answer.** Yes for the math step: the same `foc.c` takes 117 cycles with the TMU on the AM13E230, which is 0.585 microseconds at 200 MHz. The LAUNCHXL-F2800137 takes 220.6 cycles from flash, which is 1.84 microseconds at 120 MHz. That is 3.1 times faster in time and 1.9 times fewer cycles. The loop from ADC trigger to new PWM value is not measured.

Terms: [vocab](../vocab.md) (FOC, TMU, CDE). 1 kB = 1,024 bytes. Board notes: [LP-AM13E230 FAQ](../../am13e230/FAQ.md).

**Question.** TI's Arm motor-control MCU has a trig unit reached through custom instructions. On the control code TI's C2000 line is known for, does it beat the C2000?

**Vendor position.** The data sheet SPRSPC3A (Rev. A, Advance Information) lists a 200 MHz Cortex-M33 with a TMU for sine, cosine, arctangent, divide and square root as custom datapath extension instructions, and 870 CoreMark. The SDK's `benchmarks/aci` README reports per-module cycle counts for a field-oriented-control chain and gives no figures to compare.

**What was tried.** LP-AM13E230 Rev E2, AM13E2x SDK 26.01.00.03.STS, TI Arm Clang 5.1.1.LTS, SysConfig 1.28.0, DSLite 21.0.0. The C2000 bench's `foc.c` is compiled unchanged, with a small timing harness. One build uses the C library `sinf` and `cosf`; the other includes the SDK's `fastrts_tmu.h` first, which maps them to TMU instructions (the disassembly shows no library call). The step runs 1,000 times over one electrical turn from flash with the cache on, timed with the DWT cycle counter. TI's ACI benchmark (`benchmarks/aci`, TMU on) was run beside it.

**How far it got.** Run and read back, twice per build.

| Measure | AM13E230 200 MHz | F2800137 120 MHz |
|---|---|---|
| One FOC step, TMU | 117.0 cycles, 0.585 us | 220.6 cycles, 1.84 us |
| One FOC step, C library math | 655.6 cycles, 3.28 us | 400.2 cycles, 3.33 us |
| sinf plus cosf, TMU | 11.6 cycles | 24.0 cycles (flash) |
| sinf plus cosf, C library | 512.7 cycles | 190.7 cycles (flash) |
| Divide, TMU / FPU | 7.9 / 15.1 cycles | not measured |
| TI's ACI chain, FOC-only part | 555 cycles (full chain 637), PASS | not run |

**The line.** The step is measured. The trigger-to-PWM loop (`isr_entry`, `control_loop`) needs a harness that starts an ADC conversion from the MCPWM and runs the step in the interrupt; it is not written. Two numbers were unexpected. The C library `sinf` and `cosf` are 2.7 times slower here than on the F2800137, so without the TMU the two chips take the same time. A first TMU run read 1.5 cycles because the compiler moved the step out of the timed region; empty `asm` lines around the step fixed it, and the corrected figure agrees with the sine/cosine rows (117 less 11.6 leaves 105 cycles of other work, the C library build leaves 143).

**Ask.** Has anyone measured the trigger-to-PWM time on this chip with TI's `ufoc` solution and a real motor stage?
