# What should an AI coding assistant know before building or changing the MicroPython port for the MSPM0G3519 and MSPM0G3507?

That it builds with plain `arm-none-eabi-gcc` and DriverLib, needs no SysConfig, and the full image has run on an LP-MSPM0G3519 (REPL, hardware SPI, a touch screen); the LP-MSPM0G3507 image is built and emulator-checked only. This file is the short list of commands and traps, each from a build or emulator run in this folder.

Terms: [vocab](../../docs/vocab.md). 1 kB = 1,024 bytes. Checked 2026-10-20 with MicroPython v1.29.0, MSPM0 SDK 2.11.00.07, GNU Arm Embedded 14.3.1, Python 3.15 and Unicorn 2.1.4 on an Intel Mac.

**How to use it.** Read `README.md` for the sizes and the flash command. Paths below are relative to the Fox Red Labs repository root.

## Start here

| Step | Command or fact |
|---|---|
| Build one image | `cd ports/micropython && make BOARD=g3519 VARIANT=full` (`BOARD` g3519 or g3507; `VARIANT` full or min; `HEAP_MAX=<bytes>` caps the heap). Output `build-<board>-<variant>/firmware.elf` and `.bin` |
| Build all and log sizes | `ports/micropython/build_all.sh` (prints the sizes of all five images) |
| Version text | The Makefile sets `MICROPY_GIT_TAG=v1.29.0-frl1`; without it MicroPython would print this repository's git hash on the banner |
| Host check | `pip install unicorn`, then `python3 ports/micropython/tests/emu_check.py g3519 full` |
| Console | UART0 on PA10 (TX) and PA11 (RX), 115200 8N1; on the LaunchPad the XDS110 jumpers J12 and J13 connect them to the USB serial port |
| Memory | Flash at 0 (G3519 512 kB, G3507 128 kB), SRAM at 0x20200000 (128 kB and 32 kB). The linker script sizes come from `--defsym` in the Makefile |
| Clock | 80 MHz from SYSPLL, bus clock 40 MHz; if the lock check fails 20 times the code stays at 32 MHz and `machine.freq()` says so |
| Pins | `machine.Pin("PA0", machine.Pin.OUT)`; the name table is generated by `tools/gen_pins.py` from SysConfig's device data (`boards/pins_*.h`, not hand-edited) |
| Upstream | `third-party/micropython/`, unmodified; never edit it. Port changes go in this folder |

## If you see this

| What you see | Cause | Do this | Check |
|---|---|---|---|
| `import machine` raises `ImportError` | MicroPython's extension modules (`machine`, `time`, `struct`) are only compiled when the Makefile includes `extmod/extmod.mk` | Keep `include $(TOP)/extmod/extmod.mk` after `py.mk` and use `$(PY_O)`, not `$(PY_CORE_O)` | `import machine` works in `tests/emu_check.py` |
| Compile error `MP_QSTR_xxx undeclared` after adding a source file | The qstr headers in the build folder are stale | Delete `build-<board>-<variant>/` and rebuild | Build passes |
| Infinite include recursion at `extmod/modmachine.c:66` | A port file named `modmachine.c` is found before the port's own copy when `extmod/modmachine.c` includes it | Name the port's include `port_machine.inc` | Build passes |
| Redefinition of `mp_hal_pin_obj_t` or `machine_pin_obj_t` | `py/mphal.h` tests `#ifndef mp_hal_pin_obj_t`, so the port must define it as a macro and guard its header | `mphalport.h` has `#pragma once` and `#define mp_hal_pin_obj_t const machine_pin_obj_t *` | Build passes |
| `1/2` gives `TypeError: unsupported type for operator` | The minimal build has no floating point | Use `//` or build the full variant | Result `0` |
| Compile error: `DL_UART_MAIN_INTERRUPT_RX` undeclared | The interrupt masks are `DL_UART_INTERRUPT_RX` and `DL_UART_INTERRUPT_RX_TIMEOUT_ERROR`; functions use `DL_UART_Main_` | Use the names in `mphalport.c` | Build passes |
| `IOMUX_PINCMnn` index off by one | DriverLib wants the PINCM number minus 1 (`IOMUX_PINCM21` is 20) | The generated pin tables store the PINCM number and `machine_pin.c` subtracts 1 | PA10 is index 20 |
| Emulator hangs at `mp_hal_delay_ms` | Unicorn halts a core on `WFI` and nothing wakes it | `emu_check.py` patches each `WFI` to a no-op in its copy of the image; do not remove that | Check prints PASS |
| `SoftI2C` or `scan()` is very slow in the emulator | GPIO reads low, so the clock-stretch wait runs to its 50 ms timeout | `emu_check.py` returns high for GPIO inputs | Check prints PASS |
| Linker `region FLASH overflowed` on the G3507 with `VARIANT=full` | The full build is 174 kB; the G3507 has 128 kB | Use `VARIANT=min` | `g3507-min` links at 72.9 kB |

## What fits

| Image | Flash | Static RAM | Heap |
|---|---|---|---|
| G3519 full | 174 kB | 1.7 kB | 122 kB |
| G3519 minimal | 73.1 kB | 1.5 kB | 125 kB |
| G3507 minimal | 72.9 kB | 1.4 kB | 29.1 kB |
| G3507 full | 174 kB, does not fit 128 kB | | |

Sizes come from `build_all.sh`. The host check ran all four fitting images; the G3519 full image also ran on a board.

## If the console is silent on a board

The G3519 booted on its first flash with no SRAM error-correction fault. On another board or image, read `SYSCTL.NMIIIDX` first: the G3519's first SRAM bank has error correction and Zephyr's blinky stopped on it. This port writes every heap and stack word before use. Flash steps are in "Flash and run" in `README.md`.
