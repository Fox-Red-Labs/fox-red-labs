LP-MSPM33C321A (MSPM33C321A)

The MSPM33C321A is a microcontroller in TI's MSPM33 family: 160 MHz Arm Cortex-M33, 1 MB of flash, 256 kB of RAM.

Drag to turn, scroll to zoom. Tap a part or a pin.

Quick facts

BoardLP-MSPM33C321A
ChipMSPM33C321A
CoreCortex-M33
Clock160 MHz
Flash1 MB
RAM256 kB
RadioNone
Notable peripheralsHardware AES-256, SHA-256, public-key engine and random number generator, plus an immutable root of trust; two 12-bit ADCs rated 9.4 Msps; two CAN-FD; QSPI. TI lists post-quantum software library support. No NPU (TI's edge-AI device table)
On-board debug probeXDS110 with EnergyTrace, on the board. Probe firmware 3.0.0.43
Toolchains that ranTI compilers, GCC, Zephyr, FreeRTOS, MicroPython

Get it running

First blink: 11 s from plug-in to a changed blink (terminal).

  1. Build and flash the blink. The number is the blink period in milliseconds.

    mspm33c321a/blink.sh 250 <serial>

These are the recorded steps (AI assistant notes for the TI LP-MSPM33C321A LaunchPad). Run them from any terminal.

You should see: the LED toggles. The check script reads the LED pin over the probe.

What works

  • CoreMark: 544.05 (3.40 per MHz) (TI Arm Clang, bare metal, -O3; 160 MHz; 3 runs)
  • Interrupt latency, pend to first handler line: 20 cycles (bare metal; 32 MHz; 3 runs)
  • GPIO toggle: 3.02 cycles (bare metal, -O3; 32 MHz; 3 runs)
  • Blink image size: 800 B of flash, 256 B of RAM (bare metal; 32 MHz)
  • Room-occupancy AI model, one inference: 0.749 ms (-O3; 160 MHz)
  • Control loop, trigger to new PWM value: 5.029 µs (-O3, from flash; 160 MHz; 3 runs)
  • 256-point complex FFT: 0.135 ms (TI Arm Clang, -O3; 160 MHz; 3 runs)
  • AES-128: 7.35 cycles/B in hardware (TI Arm Clang, -O2; 32 MHz)
  • RTOS task switch round trip: 11.47 µs (FreeRTOS; 32 MHz; 3 runs)
  • Fastest ADC with DMA: 5.0 Msps (TI Arm Clang; 160 MHz)

Fixes

  • If you see Device Connection Error ... low power mode after the FreeRTOS blink_led example: xds110reset -s <serial> -a toggle -d 200, then flash a normal image.
  • If you see a flash write passes verify (an on-chip check and a read-back) on the MSPM33 or AM13, but the new program never starts: the LED does not change, or the old program still runs, clear FRI FRD_INTF_CTRL (0x4002900C: bit 1 data cache, bit 2 code cache; same address on both chips) while the core is halted, write, then reset.
  • If you see Verification failed: Values at address 0x00000020 do not match, fix the link line, reset and reflash.
  • If you see Case insensitivity of options has been deprecated; T must be written as t, change it to ./mspm33c321a.cmd in the example's makefile.
  • If you see FreeRTOS test hangs in an interrupt that calls xSemaphoreGiveFromISR: NVIC_SetPriority(irq, 0x40u >> (8 - __NVIC_PRIO_BITS)); the prebuilt kernel has no static allocation.
  • If you see I2C scan on the Education BoosterPack finds nothing, use SCL PB13 (pin 9) and SDA PB12 (pin 10).
  • If you see the Education BoosterPack's microphone pin ignores speech, the light sensor does not answer at 0x44, buttons read pressed, build and run portability/boosterpacks/edumkii/examples/probe (APP=probe) and look for 0x44 before debugging code.
  • If you see a C++ image that allocates stops after its first console line, add -Wl,--heap_size=32768 to the link flags.
