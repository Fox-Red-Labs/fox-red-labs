Inside the chip: a live view of a running MSPM0

Connect an MSPM0 LaunchPad (L1306, G3507, G3519 or G5187) in Chrome or Edge, or look at the sample reading below. Every block, pin and CPU share you see is read from the running chip through its debug port. The program is not stopped, changed or told about it.

Back to the Digital Lab Not connected. Works with an MSPM0 LaunchPad in Chrome or Edge.

No G3507 sample yet; a connected G3507 still works.

Colored blocks have power. Pale blocks are off. Pick a block or a pin for what it is and what this program does with it.

Filled pin: the program drives it high. Outlined: connected, low or not driven. Gray: not connected. Red number: how many times a second the pin changes.

Limits, and if the board stops answering

The view reads registers while the program runs. A pin that changes more than about 100 times a second shows "fast", and a pin driven by a timer shows no rate. The debug connection may keep the chip out of its deepest sleep, so do not use this view to measure power. If a program enters STANDBY, the debug port stops answering: the fix is in the LP-MSPM0L1306 FAQ. How each reading was checked against a known program: the MSPM0 experiment. The LP-AM243 version, which needs a few lines in the program for CPU load: the AM243 experiment.
