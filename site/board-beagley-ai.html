BeagleY-AI (AM67A)

The AM67A is a processor in TI's Jacinto 7 (J722S) family: 4x Cortex-A53 at 1.4 GHz, boots from a microSD card, 4 GB of RAM, Wi-Fi 6, Bluetooth LE. The board is made by BeagleBoard.org, not TI.

Get it running

  1. Write the card: on a Mac, with a 32 GB or larger card (not in the box): diskutil list external physical, then beagley-ai/tools/write-card.sh diskN beagley-ai-edge-ai-11.00.00.08-2025-09-06.img.xz
  2. Power and network: Ethernet first, then a 5 V 3 A USB-C supply (not in the box); the USB-C port is power only
  3. Log in: ssh root@<board address> (address from the router; host name j722s-evm)
  4. Time one model on the C7x: ONLY='ONR-KD-7060*' timeout 300 python3 /root/zoo_bench.py 30 after copying beagley-ai/bench/zoo/zoo_bench.py
  5. Same on the Arm cores: add cpu as the second argument

What works

  • Pose model on the C7x accelerator: 43.13 ms (YOLOX-S 640x640, all 274 nodes offloaded; median of 30 runs)
  • Same pose model on the Arm cores, 2 threads: 4,475.57 ms (onnxruntime CPU provider, 2 threads; median of 3 runs)
  • Object detector on the C7x: 10.15 ms (YOLOX-nano 416x416; median of 30 runs)
  • H.264 decode, 1080p, hardware: 255.9 fps (GStreamer to a fake sink; 27 to 29 percent of the four cores' time; 3 runs)
  • H.264 encode, 1080p, hardware: 110.1 fps (GStreamer, raw file in; 3 runs)
  • Decode chained into encode, 1080p: 135.1 fps (encoder imports the decoder's buffers; 3 runs)
  • Frigate detection on the C7x: 64.46 ms (recorded clip; Frigate's own timing, which includes its JPEG encode and the HTTP round trip; its CPU detector ran a different, smaller model (184.56 ms), so this is not a like-for-like speedup)
  • Qwen2.5 0.5B text generation on the Arm cores: 6.87 tokens/s (llama.cpp v0.8.0, four threads; the C7x is not used)
  • People-count demo from a USB webcam: 28.9 fps (median of five 60 s starts at 720p on a rated 5 V 3 A supply; no person was in view, so the count read 0)

Fixes

  • If you see the board is powered from your computer's USB-C port but never shows up as a network adapter, reach it over Ethernet. On the Edge AI image the USB-C port carries power only; find the address in your network's client list (host name j722s-evm).
  • If you see the Mac refuses the card, or a raw write ends with an error, use beagley-ai/tools/write-card.sh: it accepts the Mac's built-in SD slot (which lists as an internal disk) and pads the image to whole 512-byte sectors. A full card write with the current version has not been run.
  • If you see a model load never returns and the next ones hang too, reboot the board and run one model per process with a timeout. Seen once; no log of the hang was kept and the cause is unknown.
  • If you see Pose takes 43 ms where 25 to 30 ms was expected, nothing is wrong (the 25 to 30 ms was our guess from the SK-TDA4VM's 13.76 ms and its 8 against 4 TOPS): every one of the model's 274 nodes runs on the accelerator, and TI's datasheet figures for two other models are near what we measured, about 19 percent slower by the timing used here.
  • If you see FFmpeg hardware encode never finishes, or decode into a pipe stops after 3 frames, use GStreamer: v4l2h264enc for encode, and for decode into a program scale the frame before converting it.
  • If you see TI's camera demo runs at 1 fps with the C7x idle, set SOC=j722s in the environment; a login shell sets it and a plain ssh command does not, and the app then runs the model on the Arm cores.
  • If you see the board leaves Ethernet and reboots seconds after the camera demo starts, power it from a rated 5 V 3 A USB-C supply. On a wall supply of unread rating 4 of 5 starts rebooted within 15 s; on a rated one 5 of 5 held 60 s. Cause suspected, not measured.
  • If you see a program dies with Illegal instruction, the Cortex-A53 has no ARMv8.1 atomics; preload the trap library from am62l-evm/steam/lse_trap/.
