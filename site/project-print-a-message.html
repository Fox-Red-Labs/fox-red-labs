Print a message from the chip to your Mac

Flash TI's console example and read its text in a terminal on your computer, over the board's own USB cable. No extra wire.

EasyNo wiring10 min, tools installed

The MSPM0 L1306 this build runs on, drawn from its user guide. Drag to turn it.

What you need

Works on this board
LP-MSPM0L1306
Micro-USB data cablepower, programming and the serial text

Steps

Set up your computer once: 1 step. Done already? Start at step 2.

  1. Install the tools once, all free.TERMINAL

    Get CCStudio 21.0.1 from TI's CCStudio download page (1.9 GB download, 8.1 GB installed, free myTI login). It brings TI Arm Clang 5.1.1. Get the MSPM0 SDK 2.11.00.07 from TI's MSPM0 SDK download page (0.4 GB download, 2.2 GB installed). Get SysConfig 1.26.3 (TI's SysConfig page, 0.96 GB installed). Get xPack OpenOCD 0.12.0-7 from its GitHub release page (2 MB; the file xpack-openocd-0.12.0-7-darwin-x64.tar.gz on an Intel Mac, xpack-openocd-0.12.0-7-darwin-arm64.tar.gz on Apple Silicon). Then clone this repository into <repository folder>. The helper scripts sdkmake.sh and tools/ocd.sh are in it. This repo's scripts point at SysConfig 1.26.3. It came with the SimpleLink Wi-Fi SDK installer on the test Mac and sits in /Applications/ti/sysconfig_1.26.3. CCStudio 21.0.1 carries its own 1.28.1. This repo's scripts do not point at it.

    You should see: /Applications/ti/ccs2101/ccs/tools/compiler/ti-cgt-armllvm_5.1.1.LTS/bin/tiarmclang --version prints 5.1.1.

  1. Leave the jumpers as the board shipped: J16 and J17 on the XDS side, the right-hand position, which carries the chip's UART to the USB cable.BENCH

    Plug the board into the Mac with a micro-USB data cable. Find the probe's serial number: the port names are /dev/cu.usbmodem<serial>1 and ...4.

    ls /dev/cu.usbmodem*

    You should see: Two ports. The one ending in 1 is the chip's UART0 at 115200 8N1; the one ending in 4 is not used here. With probe serial <probe serial>, the port is /dev/cu.usbmodem<probe serial>1. Or read the serial with /Applications/ti/ccs2101/ccs/ccs_base/common/uscif/xds110/xdsdfu -e.

  2. Copy TI's console example out of the SDK, from the mspm0l1306 folder of this repository, and build it.TERMINAL

    Replace <repository folder> before you run this.

    cd <repository folder>/mspm0l1306 cp -R /Applications/ti/mspm0_sdk_2_11_00_07/examples/nortos/LP_MSPM0L1306/driverlib/uart_tx_console_multibyte_repeated_fifo_dma . ../mspm0g3507/mcu-bench/sdk-common/sdkmake.sh uart_tx_console_multibyte_repeated_fifo_dma/ticlang

    You should see: A build with no errors that leaves uart_tx_console_multibyte_repeated_fifo_dma/ticlang/uart_tx_console_multibyte_repeated_fifo_dma.out.

  3. Flash it with OpenOCD. tools/ocd.sh picks the probe by serial number and refuses to run if it is missing; set PROBE to your serial first (<probe serial> below stands for it).TERMINAL

    To find yours, run /Applications/ti/ccs2101/ccs/ccs_base/common/uscif/xds110/xdsdfu -e if you have CCStudio (it prints Serial Num:), else system_profiler SPUSBDataType | grep -A3 XDS110. Run it from the same folder as the build step.

    Replace <probe serial> before you run this.

    export PROBE=<probe serial> tools/ocd.sh "reset halt" "program uart_tx_console_multibyte_repeated_fifo_dma/ticlang/uart_tx_console_multibyte_repeated_fifo_dma.out verify" "reset run"

    You should see: OpenOCD ends with ** Verified OK ** after about 2 s. In the sweep this example flashed in 2.3 s.

  4. Open the chip's serial port.TERMINAL

    To leave screen, press Ctrl-A then K. This step is assembled, not recorded: the sweep read the port with a script, and this example's port was read by a script, not opened in screen.

    Replace <probe serial> before you run this.

    screen /dev/cu.usbmodem<probe serial>1 115200

    You should see: The line ==== MSPM0 Console Test ==== appears on your Mac, sent by the chip. TI's README says the example writes to the console once a second.

Read the serial output

Open the board's USB serial port in any terminal program at 115200 baud. The lines the program prints appear there.

TI's console example on the LP-MSPM0L1306

Expected result: A line of text from the chip appears in a terminal window on your Mac every time the example sends it, at 115200 baud, with no extra wires.

What this shows

  • The MSPM0 L1306 sends text to a terminal on the Mac over the board's own USB cable, using TI's unmodified example.
  • The same example printed readable text on the MSPM0 G3507 in the example sweep.
What this does not establish, and limits

What this does not establish

  • That text typed on the Mac reaches the chip: this example only transmits. The one-wire loop-back tests check both directions and are separate demos. They use J4 pin 34 to pin 33 on the G3507 and J1 pin 4 to pin 3 on the L1306.
  • That screen shows the text as the sweep script did: the sweep read the port with a script, and screen is the method this repository's LVGL demo uses. The two were not compared with this example.
  • A speed or reliability figure: the loop-back demos give those: every byte right from 9.6 kbaud to 4.5 Mbaud.

Limits to keep in mind

  • The route is written for the MSPM0 L1306. The G3507 has its own flash command and probe file, and was not run by hand in this form.
  • TI's example needs the board's shipped jumper settings; the loop-back tests move J16 and J17 and the serial window goes silent until they are put back.

Loop 2: the chip texts itself over UART

You need

  • LP-MSPM0G3507 LaunchPad development kit: TI's 80 MHz Arm Cortex-M0+ board with 128 kB flash and 32 kB RAM, a built-in debugger, three buttons, two LEDs (one RGB) and light and temperature sensors.
  • ELEGOO jumper wires (120-piece pack): Male and female breadboard wires for connecting anything to anything.

Wiring

  1. Unplug USB
  2. Move jumpers J21 and J22 down, from XDS to BP, so the UART pins reach the header instead of the USB chip
  3. One wire from J4 pin 34 (PA10, transmit) to J4 pin 33 (PA11, receive)
  4. When done, move J21 and J22 back up or the board's serial window stays silent

What was measured

  • All 2 kB right at every speed from 9.6 kbaud to 4.5 Mbaud and again from 6.4 to 10.67 Mbaud
  • Dead band at 5 to 6 Mbaud: 5 Mbaud gets 39 of 2,048 right and 6 Mbaud gets 1,921, which is 94%; 12 Mbaud sends nothing. The MSPM0 L1306 shows the same dead band. The cause was not found; TI does not document the baud divider's behavior at those settings
  • If your serial window goes silent after moving J21 and J22, move them back to XDS. TI's example README says only to jumper PA10 to PA11 and does not mention J21 and J22

Versions: MSPM0 SDK 2.11.00.07, TI Arm Clang 5.1.1; measured 2026-10-06.

Next: Find the cause of the dead band: try the fractional baud divider settings one at a time.

UART loop on one wire

You need

  • LP-MSPM0L1306 LaunchPad development kit: TI's low-cost 32 MHz Cortex-M0+ board with 64 kB flash and only 4 kB RAM, a built-in debugger, LEDs, buttons, a light sensor and a thermistor.
  • ELEGOO jumper wires (120-piece pack): Male and female breadboard wires for connecting anything to anything.

Wiring

  1. Unplug USB
  2. Move jumpers J16 and J17 to BP (left), so the chip's UART leaves the USB serial port and reaches the header
  3. One wire from J1 pin 4 (PA8, transmit) to J1 pin 3 (PA9, receive)
  4. Plug USB back in; results are read over the debugger. When done, move J16 and J17 back to XDS (right)

What was measured

  • All bytes right from 9.6 kbaud to 4.5 Mbaud and from 6.4 to 10.67 Mbaud; dead band at 5 to 6 Mbaud (5 Mbaud: 38 of 2,048 right; 6 Mbaud 1,925, which is 94%); 12 Mbaud sends nothing. The cause was not found; it is the same band as the MSPM0 G3507
  • The test program is 1.5 kB of flash and 716 bytes of RAM

Versions: MSPM0 SDK 2.11.00.07, TI Arm Clang 5.1.1, OpenOCD 0.12.0; measured 2026-10-06.

Next: Loop the other UART (PA22 and PA23) the same way.
