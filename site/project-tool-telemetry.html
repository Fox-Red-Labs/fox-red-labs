A machine's run events on your phone, no internet

Bluetooth tags on your machines, a Wi-Fi hub and a phone. Read run events, trips and run time with no internet. Built on a CC2340R5 tag and a CC35X1 hub.

HardNo wiringan afternoon with two boards

The CC2340R5 and CC35X1 this build runs on, drawn from its user guide. Drag to turn it.

Steps

  1. Check the data formats and the on-tag model.TERMINAL

    No hardware needed.

    python3 tool-telemetry/proto/test_proto.py python3 tool-telemetry/ai/train.py python3 tool-telemetry/ai/test_model.py

    You should see: OK: 9014 checks, C and Python codecs agree, the two trees' scores, then OK: C model matches the Python trees.

  2. Build and flash the tag (CC2340R5 on its probe).TERMINAL

    The flash erases the chip, so save what is on it first.

    tool-telemetry/tag/build.sh tool-telemetry/tag/flash.sh

    You should see: @TAG boot name=Tag XXXX ... ext=0. ext=0 means extended advertising started.

  3. Build and flash the hub (CC35X1 on its LP-XDS110ET).TERMINAL

    The first build makes a random Wi-Fi password and saves it in a secrets file outside the repository. The build prints the file name.

    tool-telemetry/gateway/build.sh tool-telemetry/gateway/flash.sh

    You should see: [ttgw] AP FRL-HUB-XXXX up, address 10.0.0.3 and [ttgw] scanning (rc=0).

  4. Make run events.BENCH

    Hold the tag's left button to run the machine, or press the right button for a jam. Or play a machine from the computer, giving the tag probe's port. On the phone, join Wi-Fi FRL-HUB-XXXX with the password from step 3 and open http://10.0.0.3.

    Replace <tag probe> before you run this.

    python3 tool-telemetry/sim/toolsim.py /dev/cu.usbmodem<tag probe>1 --minutes 5 --speed 3

    You should see: The Tools tab lists the machine within seconds. Tap it for its load mix. Leave the hub's Wi-Fi and the Saved tab keeps everything.

  5. Open the web dashboard in demo mode.BROWSER

    Open the web dashboard on your computer: one file, no install, no internet. With no hub in reach it replays three bench runs (tool-telemetry/results/e2e-7, e2e-5 and e2e-zephyr) at 10 times speed for about a minute. Press Replay to rerun, or drag the slider to 7:00 for the moment in the picture. Click a tag to filter its events.

    open tool-telemetry/web/dashboard.html

    You should see: Three asset tags with battery, last event, runs ended, overcurrent trips and a run timeline (over-limit events in red), plus hub status and the latest events, as in the picture. Equipment 03, a shorter run, goes Offline 30 s after its last event. The other two stay Online.

  6. Point the dashboard at the hub.BROWSER

    Put the computer on the hub's Wi-Fi (or the site network the hub joined). In Use a live hub at the page bottom, type the hub's address (10.0.0.3 on its own Wi-Fi) and press Connect. The page polls /api/info, /api/tags and /api/log every 2 seconds. It has run only against a stand-in serving a recorded hub's answers. In a narrow window it stacks into one column, as in the picture.

    You should see: Not seen on a running hub: Connected to FRL-HUB-XXXX and the asset tags from step 4 with live counts. The picture shows the narrow layout with demo data.

  7. Send it home.TERMINAL

    Start the home base on the computer with a word as a token. On the phone's Saved tab enter the computer's address and the token, press Upload, then open http://localhost:8090.

    Replace <a word you choose> before you run this.

    python3 tool-telemetry/homebase/server.py --host 0.0.0.0 --token <a word you choose>

    You should see: The fleet page fills with the uploaded records.

  8. Make the dataset and retrain the model on what you collected.TERMINAL

    Replace <work folder> before you run this.

    python3 tool-telemetry/ai/dataset.py python3 tool-telemetry/ai/train.py --from-gold <work folder>/dataset/gold/pulls.csv

    You should see: The retrained model lands in tool-telemetry/ai/out-collected/. The shipped model stays.

Evidence and limitsA CC2340R5 tag and a CC35X1 hub carried 283 of 283 run events to a phone app, median 1.4 s, no internet. Results, sources, timing and limits.

Expected result: Within seconds the phone lists the machine and counts its run events, trips and run time, and keeps them offline.

What this shows

  • A motor controller's run events reach a phone through a Bluetooth tag and a Wi-Fi hub: 283 of 283 in one simulated run, median 1.4 s.
  • Once loaded from the hub, the phone app needs no internet. The home base keeps each record once, even when two paths deliver it.
  • A one-file web dashboard shows the same data on a computer, with a timeline, and replays recorded runs with no hardware.
What this does not establish, and limits

What this does not establish

  • That it works on a real running motor. The AM13E230 firmware is built and answers commands, but no motor has spun under it.
  • That the on-tag model is right on real machines. It scored 95.9% against a simulator's own labels.
  • Range, battery life or more than two tags.
  • That live mode works on the running hub. It ran only against a stand-in, because the hub was not on this network. In the demo, the three tags are three different recorded runs, and hub uptime and frame counts are spread over the replay, not recorded.

Limits to keep in mind

  • Data on the air is not encrypted. The hub's log lives in RAM. Bench builds leave the hub's model and command endpoints open (SECURE=1 closes them).
  • The CC2340R5 has about 200 bytes of RAM left with models, commands and leases in.
  • Checked on one Intel Mac only.
