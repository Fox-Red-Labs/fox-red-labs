LP-EM-CC35X1 (CC3551E)

The CC3551E is a wireless microcontroller in TI's CC35xx family: 160 MHz Arm Cortex-M33, external flash, about 1.1 MB of RAM, Wi-Fi 6, 2.4 and 5 GHz, Bluetooth LE 5.4.

Ports and wiring demos

  • DNS ad blocker (sinkhole) on the LP-EM-CC35X1 Works: The CC35X1 answers DNS on UDP port 53: names on a blocklist get 0.0.0.0 and the rest is forwarded to your gateway.
  • Doom engine (doomgeneric and rp2040-doom's design) on the LP-EM-CC35X1 and the LP-MSPM33C321A Works: The rp2040-doom design plays all three shareware demos on the CC35X1 and the MSPM33 C321A, with frame checksums equal to a Cortex-M33 emulator.
  • ESPHome Wi-Fi device on the LP-EM-CC35X1 Works: A Wi-Fi ESPHome device runs on the CC35X1 with ESPHome's native API: a client on the board got 20 of 20 switch commands confirmed.
  • Matter thermostat over Wi-Fi on the LP-EM-CC35X1 Works: A Matter thermostat and occupancy sensor runs on the CC35X1, pairs into Apple Home and takes setpoint changes from the phone.

Fixes

  • If you see Path to programming_instructions after path correction couldn't be found, rebuild with an absolute build folder, or make the paths absolute.
  • If you see Serial silent after programming over the Wi-Fi CSI program, even TI's own examples, run full_flash_erase (about 16 s), then program as usual.
  • If you see Apple Home hangs on "Connecting", erase, program again, scan within 5 minutes.
  • If you see Matter log turns into 0x00 and 0x80 bytes once Bluetooth starts, read the start-up log in the first seconds.
  • If you see the CSI example never prints DAP streaming ready, wait for DAP inferencing ready, then send ED 08 00 9E.
  • If you see OTA menu says Invalid input or Invalid choice, send only a carriage return after each answer.
  • If you see OTA Show components in flash lists slot 2 as FAILED, menu 3, then the slot number (5 for the vendor image; about 20 s).
  • If you see ERROR rxData_DataPacketDisptcher(): Received VLAN packet - drop it, ignore it.
