LP-MSPM0G3507 (MSPM0G3507)

The MSPM0G3507 is a microcontroller in TI's MSPM0 family: 80 MHz Arm Cortex-M0+, 128 kB of flash, 32 kB of RAM.

Get it running

First blink: 2 min 29 s from plug-in to a changed blink (Mac software already installed; run from VS Code driving).

  1. Install CCStudio 21.0.1 and the MSPM0 SDK 2.11. Free with a myTI login. On a Mac, mac-setup/bootstrap.sh in the repository does both after you sign in.

  2. File, Import Project, and pick:

    /Applications/ti/mspm0_sdk_2_11_00_07/examples/nortos/LP_MSPM0G3507/driverlib/gpio_toggle_output

  3. Click the green Debug button, then Resume.

    You should see: an LED on the board blinks. The pattern is the delay in gpio_toggle_output.c: change it, build and flash again, and the blink changes.

  1. Copy TI's blink example and build it with GCC.

    cp -R <SDK>/examples/nortos/LP_MSPM0G3507/driverlib/gpio_toggle_output . make -C gpio_toggle_output/gcc MSPM0_SDK_INSTALL_DIR=<SDK> SYSCONFIG_TOOL=/Applications/ti/sysconfig_1.26.3/sysconfig_cli.sh GCC_ARMCOMPILER=<GCC folder>

  2. Flash the .out with OpenOCD.

    openocd -s <OCD>/openocd/scripts -f boards/ti/lp_mspm0g3507/support/openocd.cfg -c "adapter serial <serial>" -c init -c "reset halt" -c "program <file>.out verify" -c mspm0_board_reset -c shutdown

Replace the parts in angle brackets. Run it from the terminal in VS Code, CCStudio or any IDE.

You should see: an LED on the board blinks. The pattern is the delay in gpio_toggle_output.c: change it, build and flash again, and the blink changes.

What works

  • CoreMark: 183.61 (2.3 per MHz) (TI Arm Clang, bare metal, -O3; 80 MHz; 2 runs)
  • Interrupt latency, pend to first handler line: 29 cycles (bare metal; 80 MHz)
  • GPIO toggle: 1.0 cycles (one register write; 16 back-to-back STR minus a SysTick pair; 80 MHz)
  • Blink image size: 472 B of flash, 512 B of RAM (bare metal)
  • Room-occupancy AI model, one inference: 4.0 ms (-O3; 80 MHz)
  • Control loop, trigger to new PWM value: 12.35 µs (-O2; 80 MHz; 3 runs)
  • AES-128: 17.01 cycles/B in hardware (TI Arm Clang, -O2; 80 MHz)
  • RTOS task switch round trip: 6.717 µs (Zephyr; 80 MHz)
  • Fastest ADC with DMA: 3.93 Msps (adc12_max_freq_dma; 1k samples in 260.7 us; supply 3.29 V; 32 MHz)
  • Full redraw of a 320 x 480 SPI screen: 67.2 ms (80 MHz)

Fixes

  • If you see west sdk install prints an empty list on an Intel Mac, use the Arm compiler from SDK 0.17.4 with ZEPHYR_TOOLCHAIN_VARIANT=cross-compile and the prebuilt xPack OpenOCD.
  • If you see Zephyr blinky does not blink after a debugger soft reset, run mspm0_board_reset, or press reset.
  • If you see an aes_*, crc_*, dma_*, mathacl_* or adc12_*_dma example HardFaults with no debugger, attach the debugger with halting on, or ignore the end state.
  • If you see Board gone after sysctl_power_policy_sleep_to_standby or timx_timer_mode_pwm_x_trig_stop_restore, unplug and replug USB.
  • If you see fatal error: 'main.h' file not found (ported STM32 project), add -I"${PROJECT_ROOT}/Inc".
  • If you see error: unknown type name 'uint32_t' in Src/system_stm32g0xx.c, add #include <stdint.h>.
  • If you see make in Debug/ stops with invalid option -- O, use ccs/utils/bin/gmake -B all from CCStudio.
  • If you see Claude requested permissions to use mcp__ccs-project__changeSysConfigVersion, but you haven't granted it yet, leave CCStudio's .claude/settings.local.json out of the run, or run the skill interactively and approve.
