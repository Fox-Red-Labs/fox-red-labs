Run Arduino sketches on a TI chip

Arduino's Blink and AnalogReadSerial build unchanged through the Zephyr-based Arduino core and run on the CC2340R5 and the MSPM0 G3519. PlatformIO was not run.

HardNo wiring

The CC2340R5 this build runs on, drawn from its user guide. Drag to turn it.

Steps

Set up your computer once: 1 step. Done already? Start at step 2.

  1. Install the Zephyr 4.4.2 workspace, the compiler and the west environment with the script that builds Zephyr's blinky; NO_FLASH=1 stops it after the build so it does not touch a board.TERMINAL

    Replace <repository folder> before you run this.

    NO_FLASH=1 <repository folder>/cc2340r5/zephyr/setup-intel-mac.sh

    You should see: The script ends with NO_FLASH set. Built, not flashed.

  1. Check out the Arduino core at the pinned commit and put Arduino's API library beside it.TERMINAL

    The last line is a six-line patch that makes Serial wait for room instead of dropping bytes at 9600 baud; skip it if you only run Blink.

    Replace <ArduinoCore-zephyr folder> and <repository folder> before you run this.

    git init <ArduinoCore-zephyr folder> && cd <ArduinoCore-zephyr folder> && git remote add origin https://github.com/zephyrproject-rtos/ArduinoCore-zephyr.git git fetch --depth 1 origin af5b8610f9be6d7b962e2ba6dd8e6859697c44ff && git checkout FETCH_HEAD mkdir -p zephyr/blobs && cp -R <repository folder>/third-party/arduino/ArduinoCore-API/api zephyr/blobs/ArduinoCore-API git apply <repository folder>/portability/arduino/zephyr/serial-blocking-write.patch # CC2340R5 only

    You should see: The core folder holds zephyr/blobs/ArduinoCore-API/api, and git status shows the patched file.

  2. Build Blink.TERMINAL

    The script takes the variables the README lists (AM for the core, ZP, TC and VENV for the workspace) and stops with one line naming a missing path. Neither Zephyr tree nor the sketch is edited.

    Replace <repository folder> before you run this.

    <repository folder>/portability/arduino/zephyr/build-cc2340r5.sh Blink

    You should see: About 80 s later the build folder holds zephyr/zephyr.hex and zephyr/zephyr_crc32.hex. Blink is about 32 kB of flash and 6.1 kB of RAM.

  3. Clip the LP-XDS110ET onto the board and plug it into the Mac with its USB-C cable; the board has no USB port of its own (cc2340r5/AGENTS.md).BENCH

    Read the probe serial with /Applications/ti/ccs2101/ccs/ccs_base/common/uscif/xds110/xdsdfu -e.

    You should see: The probe shows up as an XDS110 and xdsdfu -e prints its serial number.

  4. Back up first: read the main flash and the CCFG with DSLite before the first write; the exact backup and restore commands are in ports/micropython/zephyr-cc2340r5/README.md, Flash and run.TERMINAL

    Then flash the _crc32 image, which carries the boot checksums, and reset the board.

    Replace <build folder> and <your-probe-serial> before you run this.

    $DSLITE flash -c cc2340r5/CC2340R5.ccxml -e -f -u <build folder>/zephyr/zephyr_crc32.hex xds110reset -s <your-probe-serial>

    You should see: DSLite writes and verifies the image, then the reset starts Blink. The green LED pin (DIO15) is the one Blink toggles; the check read its output register through the probe and saw bit 15 clear, then set. The LED itself was not watched.

  5. To see serial output, build AnalogReadSerial the same way (build-cc2340r5.sh AnalogReadSerial), flash it as in step 5, and open the probe's serial port at 9600 baud in any serial terminal.TERMINAL

    Replace <repository folder> and <your-probe-serial> before you run this.

    <repository folder>/portability/arduino/zephyr/build-cc2340r5.sh AnalogReadSerial # serial port: /dev/cu.usbmodem<your-probe-serial>1 at 9600 baud

    You should see: A line of a number per read: 10-bit values between about 295 and 400 on a floating A0. The first line may be garbled; ignore it.

Read the serial output

Open the board's USB serial port in any terminal program at 9600 baud. The lines the program prints appear there.

Arduino Blink and AnalogReadSerial on the LP-EM-CC2340R5

Expected result: Arduino's own Blink sketch, unchanged, runs on the CC2340R5 through the Zephyr-based core, and AnalogReadSerial prints readings at 9600 baud on the probe's serial port.

What this shows

  • Arduino's two stock examples, Blink and AnalogReadSerial from arduino/arduino-examples, build byte-for-byte unchanged for this chip and run.
  • The port is one devicetree overlay of about 40 lines for the pin map, a CMake file that includes the .ino as it is, and an optional six-line Serial patch.
  • attachInterrupt, analogWrite, SPI and Wire also ran from short test sketches.
What this does not establish, and limits

What this does not establish

  • That the LED blinked to the eye: the check read the pin's output register and the LED was not watched.
  • That ADC readings are accurate: the values come from a floating pin and show only that the call works.
  • That PlatformIO works: it was not run, so this page gives no PlatformIO steps.
  • That it works on Windows or Linux: only an Intel Mac was used.

Limits to keep in mind

  • The core's Serial drops bytes at 9600 baud on this chip unless the six-line patch is applied.
  • The CC2340R5 board file maps the red PWM LED to a timer channel that does not reach the pin; see the board page.

Arduino Blink and AnalogReadSerial on the LP-MSPM0G3519

Expected result: Arduino's own Blink sketch, unchanged, toggles PB27 on the MSPM0 G3519 through the Zephyr-based core, and AnalogReadSerial prints readings at 9600 baud.

What this shows

  • Arduino's two stock examples build unchanged for the MSPM0G3519 and run.
  • With the MSPM0 I2C pull request applied to Zephyr main, Wire, SPI, analogWrite and attachInterrupt also ran from short test sketches.
What this does not establish, and limits

What this does not establish

  • That the LED blinked to the eye: the check read the pin and the LED was not watched.
  • That ADC readings are accurate: the values come from a floating pin.
  • That PlatformIO works: it was not run, so this page gives no PlatformIO steps.
  • That it works on Zephyr 4.4.2: that release has no MSPM0 ADC or I2C driver.

Limits to keep in mind

  • Zephyr sees 64 kB of the chip's 128 kB of RAM.
  • The G3519 Wire, SPI, PWM and interrupt sketches need a Zephyr main workspace with the MSPM0 I2C pull request applied.
  • The take-it-with-you copy of the files was built for the CC2340R5 only; the G3519 copy was not built from a copy.
