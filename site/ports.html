How do I get the code I already have running on a TI board?

Coming from STM32, Arduino, ESPHome, MicroPython, Zephyr or another vendor's SDK? Pick yours below.

57 ports run on 15 TI kits and 2 other boards.

Terms are on the vocabulary page. 1 kB = 1,024 bytes. Most runs used an Intel Mac with CCStudio 21.0.1, MSPM0 SDK 2.11 and F3 SDK 9.21. The same list in Markdown is Start with your code: what ran on a TI development kit.

How a port is made

Every port followed the same five steps.

  1. Find the calls. Build the other project for the TI chip as it is. List every missing function, header and type the compiler names. That list is the whole job.
  2. Write a thin layer, not a fork. Answer those calls in one shim file on the TI side (388 lines for ESPHome's Zigbee code, 30 lines for MSPM0 apps on the CC2340R5, 13 lines for MSPM0 on the AM13E230). Leave the other project's files as they shipped, so its updates still apply.
  3. Build with the vendor's own tools. Use TI's compiler, SDK and SysConfig, from one command or the other project's own command (esphome compile). For a plain-C library with no peripheral, start from ports/minmea/build.sh: the SDK's startup file and linker file, no SysConfig. Record flash and RAM from the map file.
  4. Run it and check one thing a person would notice. The LED switched from Home Assistant, the digit read right, the packet received. For a library with no LED or serial output, read its result variables with a debugger or add a UART print. Built is not ran, and ran is not checked. Each card says which one happened.
  5. Write down where it stopped. Failures stay on the page with the exact error and the cause, whether a tool or the chip.

Questions

Is there an Arduino IDE board package for MSPM0?

No. There is a layer for your own build, and Arduino sketches run through Zephyr on the CC2340R5 and the MSPM0 G3519. You cannot pick a TI board in the Arduino IDE.

Which kit should I buy first?

The MSPM0 G3519 runs the most cards on this page: 15 of 57. Next come the MSPM33 C321A with 13 and the MSPM0 G3507 with 11. For ESPHome, take a CC35X1 for Wi-Fi, or a CC2340R5 or CC2755P10 for Zigbee only. The Board menu above lists the cards for any kit.

Which kit runs ESPHome on Wi-Fi?

The CC35X1, with the cc35xx platform. The CC2340R5 and CC2755P10 cards are Zigbee only.

How many of the Cmsemicon examples show output?

21 of the 34 have a result checked on a pin or serial line: serial text, a toggling pin or a CRC match. The other 13 ran without crashing and show nothing a probe can see.

Do all the Renesas FSP examples run on the LP-MSPM0G3519?

Four of five. The timer-triggered ADC example runs up to its DMA chain, and its two-group DMA transfer does not complete. The unchanged I2C example reports a missing ADXL345 and prints 65535 for every axis, so it needs five constants changed for the touch controller.

Does MicroPython I2C work on the LP-MSPM33C321A?

I2C opens and writes, and every read hangs until a hardware reset. Pin, float math and SPI work, and Zephyr has no ADC or PWM driver for this chip.

Can I move an STM32 HAL project to MSPM0?

Yes, with TI's migration skill. On the MSPM0 G3507 it moved STM32CubeG0 examples for GPIO, UART, ADC with DMA and PWM: 3 of 5 ran as written and 2 after corrections. I2C, SPI and timers were not run.

Can ESPHome run on a TI chip?

Yes, through the external platforms in ports/esphome-ti. cc27xx for the CC2755P10 and cc23xx for the CC2340R5 run ESPHome Zigbee devices that join Home Assistant. cc35xx gives the CC35X1 a Wi-Fi ESPHome device with the native API. You run esphome compile and esphome upload as usual, and TI's compiler and SDK do the build underneath. The cc27xx and cc23xx platforms are Zigbee only.

Does MicroPython run on a TI chip?

Yes. MicroPython's own Zephyr port runs on the CC2340R5 and the MSPM33 C321A with a >>> prompt. A new MicroPython port boots on the MSPM0 G3519 and drives a touch screen from Python.

Does Zephyr run on TI chips that have no upstream board?

On the MSPM0 L1306, yes: with the board file and a fixed GPIO driver it runs CoreMark in 4 kB of RAM. On the AM13E230 it boots and toggles an LED, and Zephyr's own blinky does not build because Zephyr has no GPIO or serial driver for that chip.

Does Rust run on MSPM0?

Yes. A Rust blinky and a serial hello run on the MSPM0 L1306 with the community embassy-mspm0 crate.

Can I run another vendor's example code on a TI microcontroller?

Often, with a thin layer. 34 Cmsemicon CMS32 examples ran on an MSPM0 L1306 with most of their main.c files untouched, and ST's STM32G4 HAL GPIO and UART examples run on the AM13E230 through TI's HAL layer. Timers, clocks and ADCs are where layers stop.

How much MSPM0 code moves to TI's wireless chips or to other MSPM0 parts unchanged?

Inside MSPM0, most examples move with a SysConfig device change (all 133 ported images that built ran on the L1306). To the CC2340R5, 0 of 10 driver examples build unchanged and 10 of 10 with a 47-line shim. The Move across TI chips page lists every test.

Can I use an AI coding assistant for a port like this?

Yes. Give it the folder and the board's AGENTS.md. The prompt at the bottom of the page does that.

Does TI's CC1407P radio host driver work on a C2000 chip like the TMS320F2800137?

Not as shipped. It fails to compile with 524 errors (no uint8_t, and a packed attribute the C2000 compiler rejects). With both worked around it compiles, but 11 of its 12 message structs come out a different size from the bytes on the SPI wire, because the C28x has no 8-bit byte. A field-by-field packer gives the right transmit bytes (17 of 17 cases equal to an Arm host, no radio attached), and the driver does not call it. On MSPM0 hosts it runs: 21,658 of 21,658 packets on an MSPM0 G5187.

Hand the folder and its AGENTS.md to your coding assistant
