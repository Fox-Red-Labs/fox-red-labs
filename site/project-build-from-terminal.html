Build and flash a TI example from one terminal

One make line builds TI's example and one flash line puts it on the board. There is no window to click, so you can run it from a terminal.

EasyNo wiring5 min once the tools are installed (12 GB, once)

The MSPM0 L1306 this build runs on, drawn from its user guide. Drag to turn it.

What you need

Works on this board
LP-MSPM0L1306
Micro-USB data cablepower and programming

Steps

Set up your computer once: 1 step. Done already? Start at step 2.

  1. Install the tools once, all free: CCStudio 21.0.1 from TI's CCStudio download page (1.9 GB download, 8.1 GB installed, free myTI login) (it brings TI Arm Clang 5.1.1), the MSPM0 SDK 2.11.00.07 from TI's MSPM0 SDK download page (0.4 GB download, 2.2 GB installed), SysConfig 1.26.3 (TI's SysConfig page, 0.96 GB installed), and xPack OpenOCD 0.12.0-7 from its GitHub release page (2 MB; the file xpack-openocd-0.12.0-7-darwin-x64.tar.gz on an Intel Mac, xpack-openocd-0.12.0-7-darwin-arm64.tar.gz on Apple Silicon).TERMINAL

    Then clone this repository into <repository folder> for the helper scripts sdkmake.sh and tools/ocd.sh. SysConfig 1.26.3, the version this repo's scripts point at, came with the SimpleLink Wi-Fi SDK installer on the test Mac (it put it in /Applications/ti/sysconfig_1.26.3); CCStudio 21.0.1 carries its own 1.28.1, which this repo's scripts do not point at.

    You should see: /Applications/ti/ccs2101/ccs/tools/compiler/ti-cgt-armllvm_5.1.1.LTS/bin/tiarmclang --version prints 5.1.1.

  1. Plug the board into the Mac with a micro-USB data cable.BENCH

    It shows up as an XDS110 probe with two serial ports; there is no driver to install. Read your probe's serial number from the port names.

    ls /dev/cu.usbmodem*

    You should see: Two ports named /dev/cu.usbmodem<serial>1 and ...4. The part between usbmodem and the last digit is your probe's serial number.

  2. From the mspm0l1306 folder of this repository, copy one of TI's examples out of the SDK and build it with one make line.TERMINAL

    Any example folder works the same way; the blink is the one that was timed.

    Replace <repository folder> before you run this.

    cd <repository folder>/mspm0l1306 cp -R /Applications/ti/mspm0_sdk_2_11_00_07/examples/nortos/LP_MSPM0L1306/driverlib/gpio_toggle_output . ../mspm0g3507/mcu-bench/sdk-common/sdkmake.sh gpio_toggle_output/ticlang

    You should see: A build with no errors that leaves gpio_toggle_output/ticlang/gpio_toggle_output.out. It took 3.3 s for the blink. 167 of the board's 170 SDK examples build this way.

  3. Flash it with OpenOCD. tools/ocd.sh picks the probe by serial number and refuses to run if it is missing; set PROBE to your serial first (<probe serial> below stands for it).TERMINAL

    To find yours, run /Applications/ti/ccs2101/ccs/ccs_base/common/uscif/xds110/xdsdfu -e if you have CCStudio (it prints Serial Num:), else system_profiler SPUSBDataType | grep -A3 XDS110. Run it from the same folder as the build step.

    Replace <probe serial> before you run this.

    export PROBE=<probe serial> tools/ocd.sh "reset halt" "program gpio_toggle_output/ticlang/gpio_toggle_output.out verify" "reset run"

    You should see: OpenOCD ends with ** Verified OK ** in about 0.6 s, and the RGB LED cycles.

If something goes wrong

Your tools live somewhere other than /Applications/tiEdit the paths at the top of mspm0g3507/mcu-bench/sdk-common/sdkmake.sh.
Nothing appearsTry another cable; a charge-only cable looks the same.
The build cannot find SysConfig or the compilerThe paths in sdkmake.sh do not match your install (step 1).
OpenOCD prints `ErrorChecksum mismatch - attempting binary compare` first; that is normal, and the next line is the real result.

MSPM0 LaunchPad: make and OpenOCD

Expected result: One build line and one flash line take TI's example from the SDK to a running program on the board in under 5 seconds of machine time. No window, nothing to click.

What this shows

  • TI's example builds with one make line and flashes with one OpenOCD line on the MSPM0 L1306: 3.3 s and 0.6 s for the blink, and the RGB LED cycled.
  • 167 of 170 of the board's SDK examples build from the terminal, and all 148 that do not write the boot configuration were flashed and run by script without losing the debugger.
What this does not establish, and limits

What this does not establish

  • That an AI assistant can type these lines. The route was timed with a script and by hand, not with an assistant.
  • That the 3 examples that do not build are the chip's fault: their causes were not all traced.
  • That every example does something you can see: many need extra wiring to show they work.

Limits to keep in mind

  • The helper scripts look for the tools in the TI install folders; another place is named with the FRL_ variables the start page lists. Checked on one Mac.
  • tools/ocd.sh refuses to run until PROBE is set to your probe's serial number.

SimpleLink LaunchPad: make and UniFlash

Expected result: A build of about 22 seconds and a flash of about 7 seconds put TI's blink on the board, and the red LED toggles once a second, from a terminal and with no window.

What this shows

  • TI's blink for the CC2340R5 builds with one make line and flashes with one UniFlash line from a Mac terminal, and the host saw the red LED blink.
  • The gotchas are known and written down: probe seating, the connection file, the SDK's build paths and the verify mismatch.
What this does not establish, and limits

What this does not establish

  • A typical first-time duration: the 9 minutes included 8 of probe trouble, and the board was used, not sealed.
  • That verify works: with -v UniFlash reports a mismatch in the boot configuration area on every image flashed, cause unknown.
  • That an AI assistant can type these lines unaided; one in VS Code did them in a recorded run.

Limits to keep in mind

  • The probe is a second board to buy; the CC2340R5 cannot be powered or flashed without one.
  • UniFlash's command line needs a connection file that no TI command-line tool writes; step 3 uses CCStudio to make it.

C2000 LaunchPad: scripted build and load

Expected result: A build of under 5 seconds and a RAM load of under 5 seconds, then the LED pin toggling, all from a terminal. A flash image needs the FLASH build and was not timed for the blink.

What this shows

  • TI's blink example for the LAUNCHXL-F2800137 builds from a Mac terminal in 4.6 s and runs from RAM in 3.9 s, with the LED pin seen toggling.
  • 138 of 139 C2000Ware examples for the chip build by script with TI's own flags plus three additions the projects do not list.
What this does not establish, and limits

What this does not establish

  • A flash write of the blink: the timed load was to RAM. The flash route is described but the blink was not timed from flash.
  • That a person watched the LED: the pin was sampled by the script.
  • Anything about Apple Silicon or CCStudio's window.

Limits to keep in mind

  • The probe may need a firmware update before TI's tools connect.
  • 4-pin JTAG does not work on the board as shipped; the connection file must use 2-pin cJTAG.
  • The route needs CCStudio's scripting runner because UniFlash's command-line calls each reconnect.
