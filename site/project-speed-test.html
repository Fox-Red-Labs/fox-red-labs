Measure the chip's speed with CoreMark

Build the standard CoreMark benchmark, run it on the board and work out iterations per second. The same source runs on every board, so the numbers compare.

MediumNo wiring85 s to rerun

The MSPM0 L1306 this build runs on, drawn from its user guide. Drag to turn it.

What you need

Works on this board
LP-MSPM0L1306
Micro-USB data cablepower and programming

Steps

Set up your computer once: 1 step. Done already? Start at step 2.

  1. Install the tools once, all free.TERMINAL

    • Get CCStudio 21.0.1 from TI's CCStudio download page (1.9 GB download, 8.1 GB installed, free myTI login). It brings TI Arm Clang 5.1.1.LTS.
    • Get the MSPM0 SDK 2.11.00.07 from TI's MSPM0 SDK download page (0.4 GB download, 2.2 GB installed).
    • Get SysConfig 1.26.3 (TI's SysConfig page, 0.96 GB installed).
    • Get xPack OpenOCD 0.12.0-7 from its GitHub release page (2 MB; the file xpack-openocd-0.12.0-7-darwin-x64.tar.gz on an Intel Mac, xpack-openocd-0.12.0-7-darwin-arm64.tar.gz on Apple Silicon).
    • Get the Zephyr SDK 0.17.4 Arm toolchain, toolchain_macos-x86_64_arm-zephyr-eabi.tar.xz, from the Zephyr SDK releases on GitHub. Unpack it into ~/zephyr-toolchain, as mspm0g3507/zephyr/setup-intel-mac.sh does. The run script uses its arm-zephyr-eabi-nm to find the result in RAM.
    • Clone this repository into <repository folder>. CoreMark's source is in mspm0l1306/bench/coremark. This repo's scripts point at SysConfig 1.26.3. It came with the SimpleLink Wi-Fi SDK installer on the test Mac and sits in /Applications/ti/sysconfig_1.26.3. CCStudio 21.0.1 carries its own 1.28.1. This repo's scripts do not point at it.

    You should see: /Applications/ti/ccs2101/ccs/tools/compiler/ti-cgt-armllvm_5.1.1.LTS/bin/tiarmclang --version prints 5.1.1, and ls ~/zephyr-toolchain/arm-zephyr-eabi/bin/arm-zephyr-eabi-nm finds the tool.

  1. Plug the board into the Mac.BENCH

    List your probe's serial number with xdsdfu -e, run from CCStudio's ccs_base/common/uscif/xds110/ folder. Then set it for this shell with export PROBE=<serial>. Every script flashes through mspm0l1306/tools/ocd.sh, which refuses to run without PROBE. Close any serial window open on the board.

    /Applications/ti/ccs2101/ccs/ccs_base/common/uscif/xds110/xdsdfu -e

    You should see: xdsdfu lists the probe and its serial number.

  2. From the repository folder, go to the CoreMark folder and build at -O3 and 32 MHz.TERMINAL

    cd mspm0l1306/bench/coremark ./build.sh O3 32

    You should see: A build with no errors that leaves build-O3-32/coremark.out and its map.

  3. Flash it, fill RAM with a pattern, run 16 seconds and read the result from RAM through the debugger.TERMINAL

    No serial window is needed. The last number is how many seconds to let it run.

    ./run.sh O3 32 16

    You should see: Correct operation validated, Iterations : 1000 and Total ticks : 408864304, or very close, and a stack line saying the stack stayed inside its reserved space. The line Iterations/Sec : 83 is rounded because float printing is off to save RAM.

  4. Work out the score yourself: iterations divided by ticks at the clock speed.TERMINAL

    You should see: 1k iterations divided by 408,864,304 ticks at 32 MHz is 78.27 per second, or 2.446 per MHz.

If something goes wrong

A tool lives elsewhereChange the path at the top of build.sh, run.sh or tools/ocd.sh; the scripts expect each tool at the path set there.
You want to put the board back as it cameRead the out-of-box image before you flash anything; the folder mspm0l1306/data has the image read from the test board.
The build cannot find the SDK or compilerThe paths at the top of build.sh do not match your install.
The stack line says OVERFLOWThe score is not valid even if it looks plausible, because this chip has no memory protection.
The number is off by more than a few percentCheck CPUCLK_FREQ in the generated ti_msp_dl_config.h. Check the optimization level too: -Os and -Oz score 47.35 and 41.63. Then run it three times.
More troubleshooting
Your tick count differs from run to runThe setup is the cause: every recorded run, by hand and with an AI assistant, gave 408,864,304.

Bare-metal CoreMark on the LP-MSPM0L1306

Expected result: CoreMark prints Correct operation validated and its tick count is 408,864,304 or very close, so the score works out to 78.27 per second at 32 MHz. Build and run take well under a minute.

What this shows

  • The MSPM0 L1306 scores 78.27 CoreMark per second, 2.446 per MHz, at 32 MHz with TI Arm Clang -O3 and no operating system. The run passes CoreMark's own correctness check.
  • Every saved run gave the same tick count, 408,864,304, so a different number points at the setup.
What this does not establish, and limits

What this does not establish

  • That other chips or compilers score the same. The comparison across boards is on the Benchmarks page. A different compiler or operating system changes the score: GCC 12.2.0 -O3 gave 54.62 on this board, and 59.70 under Zephyr.
  • The printed Iterations/Sec : 83 as the score: it is rounded; the score is computed from the ticks.
  • That this is an official EEMBC-certified result: it is this run of the unmodified EEMBC source, with a new port layer.

Limits to keep in mind

  • CoreMark's 2 kB work area sits on the stack, so the build reserves a 3 kB stack. The deepest use in this run was 2.9 kB, which leaves little room on a 4 kB chip.
  • The scripts hard-code Mac paths and the probe serial, and need the Zephyr SDK's nm.

Bare-metal CoreMark on the LP-EM-CC2340R5

Expected result: The serial report ends in BENCH DONE and shows CoreMark passing its own check at about 111 iterations per second at 48 MHz.

What this shows

  • The CC2340R5 scores 111.09 CoreMark per second, 2.31 per MHz, at 48 MHz with TI Arm Clang -O3 and no operating system.
  • Within 1% per MHz of the MSPM0 G3507 at full speed, which has the same core and compiler and scores 2.30 per MHz at 80 MHz.
What this does not establish, and limits

What this does not establish

  • A repeat: each build was run once, so the score is a single measurement.
  • That the compiler alone explains the gap to Zephyr with GCC on the same chip, which scored 84.07. That comparison changes the compiler, the operating system and Zephyr's timer setup at once.
  • An official EEMBC-certified result.

Limits to keep in mind

  • The probe is a second board to buy; the CC2340R5 cannot be powered or flashed without one.
  • UniFlash's verify (-v) reports a mismatch in the boot configuration area on this chip, so the script flashes without it.
